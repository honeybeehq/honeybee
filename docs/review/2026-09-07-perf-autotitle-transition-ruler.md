# Automatic-title transition measurement review

Revision 93260cb415729fa2e7c619bf584ab88a63de86ecdf7d5c953215f3a5b226c90f is approved for controlled measurement. The [draft review](../performance/2026-09-07-exhaustive/designs/autotitle-architecture/transition-ruler-v1-review.md) found a provider guard returning a function instead of throwing, twice the intended expiry sample count, an implicit microtask timing boundary and sidecar claims stronger than the assertions. Full revision diff review confirms all four fixes. The provider's held promise is rejected only after scan timing ends, and exact context, outcome, serialized bookkeeping and cycle counts are checked.

The first draft smoke failed because a baseline expiry cycle includes both a launching scan and a drain scan, each reading the giant mailbox. The corrected expectation of two reads is justified by source and retained in the passing draft. Both original attempts remain archived. The revised smoke and Mini smoke/canonical A/A runs complete all four scenarios.

Provenance correction: the author initially supplied two incorrect revision/smoke hashes in message 4217. Direct parent hashing establishes ruler 93260cb4 and smoke cb01287d. The supplied 09e340b1 and 6d206956 values are invalid and are not used as evidence. This was a repeated handoff failure; the standing rule now requires reading completed hash-command output before quoting a digest, or omitting it. Parent verification always hashes actual bytes.

The canonical control uses 30 measured samples per side for every scenario. One changed bee rotates through a thin-deferred fleet of 1000. The all-changed case appends one envelope-only message to every bee before each scan, so history grows by the recorded mutation count. Expiry uses one 100k-message mailbox and 38 total launch cycles per side, including first/warm/diagnostic cycles. Its measured numbers cover launching scans only, not drain scans or rejection completion. Stress scans ten 20k-message mailboxes. These are deliberate workloads, not observations about a live user fleet.

The offline heap inspector is a separate structural tool. A three-entry synthetic closure proves it can follow the named context slot through the Map table to three entry objects, and a released closure produces no matching slot. Real baseline warm/released snapshots contain no candidate slot; the CoreStore instance disappears after release. It does not calculate dominators or attribute retained bytes. Future candidate snapshots must prove that the inspected slot is the actual source cache before counts are interpreted.
