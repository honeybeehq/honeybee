# Codex Cell access-only refresh

This change is source-only until reviewed and explicitly deployed. No agent may enroll credentials, refresh live tokens, or restart another Bee. T11's existing deploy HOLD remains.

Apiary renews satellite Codex leases approximately 60 minutes before expiry, according to Queen's Apiary source review (leases/domain.ts:9–15,111–112,140–150; creds/domain.ts:578–624). Studio apiaryd availability remains necessary. Honeybee's receiver account.lease.install publication triggers reconciliation after the atomic file writes. A regular daemon tick also reconciles, so a deferred publication callback is recoverable. Authority refresh alone does not deliver a satellite lease.

Every sandboxed Codex auth.json and .codex/auth.json must be a bounded, valid, explicit access-only document with tokens.refresh_token="". Native/full/unproven documents refuse with auth_needed. Native enrollment is a human operation. Validated bytes become immutable host snapshots under dataDir/cell-access/accountHash, never the shared account home or a Cell-writable directory. Projection mounts these snapshots read-only. Garbage collection retains every digest referenced by a non-stopped runtime plus the newest eight snapshots; 129 successive publications are covered by a synthetic fixture.

Completed lease publication coalesces material inspection per account and, for new bytes, queues one generation-fenced stop with waitForIdle and thenRevive per affected Bee. Core claim waits for idle; it never signals a running turn. The next generation remounts renewed material. Operator control, account changes, moves and handoffs fence stale replacement intent. A mooted command can be re-evaluated rather than silently blocking turns forever. Unchanged bytes do not trigger replacement even if a publisher increments its material generation. The Apiary RENEW_RETRY_FLOOR behavior is supplied by Queen's separate source review, not independently verified from this Honeybee checkout.

A single turn that extends past the old projection expiry receives a quiet, visible auth_needed. It is not interrupted or repeatedly revived. If the relaunch path is unavailable before the confirmed expiry, Tormod must knowingly accept visible auth_needed and manually restart at a safe boundary. Genuine harness authentication failures are preserved; Cell maintenance never relabels and clears them as its own attention.

## Identify old Cells and recover manually

From the host operator environment, run `hive view <bee-id> --json`. The response carries `bee.substrate`, `runtime.generation`, `runtime.state`, and `runtime.credentialStamp.cellProjection`. A live Codex Cell with a missing cellProjection is an old, unreceipted generation and requires retirement or an operator-controlled restart before rollout. A missing mountedAt means the daemon has not recorded the bound process in a distinct user namespace; a missing authenticationHintAt means no completed harness turn has yet reported authentication. These are metadata receipts, not token contents. The prepared receipt contains path-keyed document digests and the mounted material's expiry, never credential bytes.

Do not infer a safe boundary from silence. Wait until `hive view <bee-id> --json` reports `runtime.state` as `idle`, with no active move/handoff. Tormod may then run `hive stop <bee-id> --json`, wait until that exact generation reports `stopped`, and run `hive revive <bee-id> --json`. Confirm the new runtime generation, cellProjection.mountedAt and, after a completed harness turn, cellProjection.authenticationHintAt. The authentication field is a Cell-controlled harness hint, not host proof; prepared and mounted receipts are the host evidence. If the Bee is already stopped, only the explicit revive is needed. No such live actions were performed by this worker.

## Verification scope

Synthetic credentials only on netcup-3: strict schema/file refusal, immutable snapshot replacement, live snapshot retention across 129 publications, quiet expiry and async boot, operator-control cancellation, moot re-admission, safe-boundary successor generation, durable mailbox, and generation-fenced receipts. Existing sandbox/driver suites run through the owned Node overlay with no guard bypass. Central refresh RPC fixtures use an explicit satellite configuration and a registered fixture operator; a separate strict fixture proves unattributed refusal remains intact. These are targeted suites, not a full npm test claim.

Studio apiaryd is the sole renewing issuer: Queen confirms a 30-second scan, Codex renewal 60 minutes before expiry, and 2–10 minute retry/backoff. If Studio apiaryd is down for approximately the final hour before expiry, satellite leases can lapse. An expired/superseded Cell 401 stays Bee-local and does not flip the account status or reset the issuer’s reactive retry floor. An extended lease with identical valid mounted/host digests updates only the current generation’s expiry and material metadata inside a fenced store transaction. Digests are unchanged and no restart is queued. The expiry is monotonic and cannot exceed the published lease or authority expiry.

## Source ordering confirmation and residuals

At source 0dbbbc4d, lease installation has two phases, not simply “the expiry row is written last.” accountsService.ts:1742 first writes the incoming origin (including its new expiry) with materialPublished=false for fenced/enrolled leases. It then atomically writes the primary files (:1753) and mirror (:1761), and only afterwards sets the final published origin (:1765) and invokes onInstalled (:1767). authDeathMaterial refuses unpublished or generationless leases (:887). recordCellCredentialProjection requires that live material before accepting the expiry (daemon.ts:1643–1645). Codex file publication is synchronous on the single writer, with no keychain await between these writes. Thus an intermediate new expiry cannot authorize a projection of old bytes; a failed partial install remains unpublished. Legacy generationless delivery cannot produce the required material stamp. The unchanged fast path (:1704–1716) first compares the complete lease origin and installed primary bytes, so it does not advance expiry while retaining old primary bytes.

Crash-left `.stage-*` files now have an owned-directory sweep: regular non-symlink staging files owned by the daemon, read-only and older than ten minutes are removed by snapshot GC. Fresh stages are retained. This closes the prior indefinite-stage residual recorded at 0dbbbc4d. The ordinary finally unlink can still surface a plain filesystem error instead of a typed refusal; this recorded low residual is owned by T11g worker 265af7ab-4123-41a6-8779-aeb77951a790. Per-Bee maintenance isolation prevents that error from stalling the node.

Per Quiet's design approval, running the preflight still requires its full C1–C5 conditions, including a pinned clean checkout, sanitized env -i invocation, reviewed Node version and one run per node under its GO. It also requires new authorization from Needle and Queen's credential-read approval. Source approval grants none of those execution permissions. No preflight run has occurred.


New-byte replacement is limited to one account/publication round per sliding six hours. All Bees needing the same host-digest publication share a round. A distinct second round is refused, its Cells receive visible cell_replacement_rate_limited attention, and one constant-code line is logged. The window derives from durable command history and survives daemon restart; it resumes automatically after the window rather than creating a permanent latch. Operator pause, placement and generation fences remain authoritative. This guard does not count same-byte expiry extensions as replacements.
