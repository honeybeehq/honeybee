# Parent pre-synthesis findings

Fable package fully read at frozen hashes d26c3961 / 635e0ade. No verdict until second package and judge.

1. Gate backoff predicate must preserve truthiness of bookkeeping.lastAt. Sketch omits it. At now=0, claimed lastAt=0 is intentionally false in existing autoTitleDecision; a failed attempt must not become a new backoff skip.
2. record-after-read based only on a later committed stamp is unsafe with reentrant custom dependencies. A listMessages/read or loadState/saveState callback can commit a mutation or complete a rollback before record. No awaits does not prohibit synchronous callback mutation. Pairing needs either a source-owned synchronous combined read or bracketing committed stamps, with null at either boundary invalidating publication. Gate freshness around loadState ordering also needs explicit ownership.
3. Per-partition COUNT/MAX serialization invalidates on markDelivered, contradicting the claimed delivery silence. Combine counts and global max if membership is the intended fact. New invalidation is conservative but forfeits an important realistic-workload win.
4. The sketch changes loadState-before-listMessages ordering. If optional stamp enables a documented pure read contract, state that precisely; preserve ungated custom-deps behavior and avoid claiming arbitrary callback trace equivalence.
5. Map prune-to-visited is bounded but an early break evicts later baselines. This preserves behavior but can cause repeated cold reads. Bound claims should reflect early returns while inflight or disabled too, not promise pruning every invocation.
6. Body-free giant probe timing is unmeasured. Hundreds-of-us and ~400x assertions are hypotheses, not extrapolations from a measured COUNT/MAX query. Need query-plan plus VDBE check, raw probe measurements, and whole dispatcher captures before acceptance.
7. Core fact says byte-identical message contents, but delivery and urgency fields can differ. Exact invariant is immutable ordered IDs/bodies for title normalization, not full MessageRow equality.
8. Bracketing independent custom callbacks is not a universal fix: listMessages itself can return a speculative snapshot after opening and rolling back a transaction while outside stamp reads both observe the unchanged committed state. A source-owned paired read or explicit truthful opt-in callback contract must be the trust boundary. Do not overpromise safety for arbitrary implementations of the new dependency. Existing custom dependencies should keep the old path by default.

10. total_changes scratch first run incorrectly expected missing-message markDelivered to return an unapplied result; actual API throws. Corrected to assert that throw, then used real duplicate delivery to prove a no-op. No production change or relaxed behavior test.

Source confirms mail.deliver_noop append. Corrected the diagnostic to require an increment. This is concrete false-invalidation cost for a global connection token, not a production bug.
12. Sol draft read end-to-end at design40c667de/signatures7db34f18 before author final freeze; rehash and reread if revised. Core initial-token fallback needs an explicit deletion contract. An existing-on-open Bee can have the initial token, then delete removes its absent map entry and returns the same initial token if the getter falls back blindly. Store-backed fresh-roster pruning protects the current caller but does not prove the advertised Core content-token invariant. Prefer a concrete missing variant or validated lazy per-live-Bee token allocation, and test existing-on-open deletion directly. No silent historical tombstones.
13. Stage at the successful SQL mutation, before later fallible audit/projection work. Nested transactions join rather than savepoint: an outer callback can catch a nested send error after INSERT and commit that row. Staging only after full method success would miss it. Real opts.now can throw during audit after INSERT; use that cheap public seam to prove the boundary if this design proceeds.
14. Consider subtracting Sol selected-body launch and summary-policy rewrite. Fable-style quiet skips can retain only signature + committed token, keep current normalization and full launch read, and solve the repeated unchanged scan. Expiry-read optimization would then be a separate measurable candidate. The private store-only capability from Sol is the useful boundary graft.
15. Candidate refinement for the token contract: lazy per-live-Bee tokens. On first committed read, check Bee existence once and allocate a token only for a live row; missing returns an explicit missing variant and does not insert. Existing registered keys read from the map. Stage changes only for registered keys; delete commit removes the key, while recreate in the same outer transaction overwrites its staged effect before publication. No token ever issued for unregistered keys, so their changes need no tracking. This bounds the map by current observed live Bees and avoids per-create overhead when naming never uses the API. Close clears the map and later reads must fail, not return stale entries. This is a proposed correction, not yet judged or implemented.
16. Quiet backoff reuse can call the EXISTING autoTitleDecision(bee, [], verifiedBookkeeping, now) and honor only its skip result. The skip branches precede content checks, so this preserves lastAt truthiness and every existing retry edge without duplicating the backoff predicate. Deferred unchanged is already a signature-tied shortcut. All generate/defer-new paths still read and normalize fully, preserving exact launch context with no new summary policy.
