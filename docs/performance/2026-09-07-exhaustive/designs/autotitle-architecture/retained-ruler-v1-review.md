# Retained-memory ruler draft review

Reviewed tool SHA-256 d17350089b72ae8075f25a3caed583c425270ac1bbb4f869447ada5d59f04aba. Decision: revise before canonical. Independent serial child processes, one shared verified fixture, full-row PK proof and explicit native-memory limitations are sound foundations. No production changes are requested by this review.

## Required revisions

1. Preserve this tool as v1 and preserve both original smoke reports and four snapshots. In snapshot mode, omit derived numeric deltas and mark every memory reading diagnostic-only. Snapshot serialization and deeper collection change later phases. Use mode=none for numeric comparisons. Neither within-mode symmetry nor one A/A pair proves the artifact cancels between different implementations.
2. Add a constructed phase before any dispatcher scan. Rename today's cold to firstScan, explicitly warm process/module/fixture caches. Keep warm, rosterDeleted and released. Cache entries can already exist after the first scan, so today's cold-to-warm misses initial cache retention entirely.
3. Use independent serial ABBA child order with unique per-run outputs/artifact paths, at least two children per side. Retain all raw phase readings and per-run deltas. Record the exact order. This permits a minimal A/A variability check; it is still descriptive evidence rather than a statistical guarantee. No aggregate performance claims from the single-pair v1 smoke.
4. Remove the claim that warm-to-released bounds or attributes dispatcher+store retained memory. Deletion adds audits, changes prepared statements/SQLite caches, and invokes more code before release. Call these whole-process phase differences. A/B same-phase differences and phase-difference comparisons remain signals subject to A/A variation. heapUsed is managed-heap occupancy after a best-effort collection, not exact live bytes. RSS is not a cache measurement.
5. Keep the identical fixed GC protocol, but yield one event-loop turn between calls and before the reading to avoid treating same-turn temporary retention as live application state. Record that exact protocol, without tuning repetitions to chase a smaller number. Assert scale/mode and the actual scan budget. Smoke is 10 scans, canonical is 32 with current W, not <=10 generally; explicitly verify elapsed logical time stays inside seeded backoff.
6. Prove quiet state equality outside measurement using a scoped state-hash helper over dumpState plus audit, with large temporaries confined to the helper and collected before readings. Preserve seeded audit/sidecar checks. Check sidecar stability again after the empty-roster scan. Ensure error cleanup closes any opened store before removing its owned disposable files. Use fileURLToPath for self-spawning.
7. Correct the proposed private-Map fallback. Reflect cannot access a closure-local Map, and no diagnostic property/API is authorized merely for a benchmark. State that cache bounds need implementation-specific behavioral evidence and offline retaining-path analysis. A later test can instrument existing Map operations carefully if needed; do not promise map-size equality or a reflection seam that does not exist. The design bound is at most entries for the last full active-untitled roster, not equality to roster size and not instantaneous pruning while scans return early.

## Evidence checked

Both smoke hashes match the handoff and completed=true. In mode=none, side 0 warm heapUsed is 10,126,072 B and released is 10,150,080 B. The positive difference alone shows why it cannot be a retained-total bound. The corresponding snapshot run reports warm 10,124,288 B and released 6,130,704 B, while RSS rises from 107,331,584 B to 142,032,896 B. The author correctly disclosed this measurement effect; the executable report must enforce the scope too.

Root/tool/boot end checks in the parent cover serial children adequately. No additional instrumentation framework, production API, Mini activity, timing claims or broad test launches are requested. After the bounded revisions, run node --check and structural Studio A/A smoke in both modes, retaining failed attempts if any. Freeze the revised bytes for parent review before canonical.
