# Quota evidence contract (A)

Provider evidence is not account recovery status. No consumer infers rotation or continuation from text.

## Runtime evidence

`FlagEvidenceLike` / `FlagEvidence` keep their existing fields and gain optional `quota: QuotaBoundary` and `eventId: string`. Only resource_blocked/set carries quota. Existing `turn: {messageIds: number[], progress: 'none' | 'some' | 'unknown'}` is captured by the driver before turn_ended. `QuotaBoundary` is owned by `v2/core/src/quota.ts`:

```ts
type QuotaBoundary = {
  harness: 'claude' | 'codex';
  window: 'five_hour' | 'weekly' | 'other';
  resetsAt: number | null;
  providerCategory: 'rate_limit_event' | 'synthetic_limit' | 'errored_result_limit' | 'rateLimitReachedType' | 'usageLimitExceeded' | 'text_fallback';
};
```

Reset is epoch milliseconds; null means provider supplied no unambiguous instant. Never invent an instant from a local-clock phrase such as '2pm (Europe/Oslo)'. Raw evidence retains that phrase. Window other means unspecified or a different provider window. Claude native rateLimitType supplies the window (seven_day, seven_day_opus and seven_day_sonnet normalize to weekly); rejected/blocked status is quota exhaustion. allowed statuses clear the existing condition. Unknown non-allowed statuses retain legacy resource evidence and receive text_fallback (other/null), preserving the old exhaustion classification. Categories currently emitted: rate_limit_event, synthetic_limit, errored_result_limit, rateLimitReachedType, usageLimitExceeded, text_fallback.

Claude fallback recognizes the entire exact `You've hit your limit · resets …` (five-hour), `You've hit your weekly limit · resets …`, `You've hit your 5-hour limit · resets …`, or `You've hit your five-hour limit · resets …` only in a <synthetic> assistant or native error:'rate_limit' envelope or an is_error result. Genuine assistant prose, including the exact text, stays speech. The existing daemon isRateLimitCause predicate remains authoritative fallback evidence: rate limit/rate-limit/rate_limit, 429, quota exceeded/exhausted, and usage limit in provider error contexts produce text_fallback with other/null. Precise structured/exact shapes take priority. Ordinary assistant prose never enters this fallback. Auth classification retains priority for non-native quota errors. Plain overload without those legacy markers remains resource_blocked without quota. text_fallback is lower confidence than native evidence: it deliberately preserves historical exhaustion behavior, including transient 429/willRetry errors and unknown non-allowed Claude statuses. B/C/F must not treat it as a known window or promise a capacity-return time. The legacy top-level flag may still carry a native reset hint even when quota.window/reset remain other/null; that hint is not a fleet-capacity assertion. Codex rateLimitReachedType is a non-null gate, not a window selector. Select exhausted windows from primary/secondary usedPercent >= 100 and windowDurationMins (300 or 10080); when several are exhausted retain the latest known reset, with unknown reset taking precedence. No exhausted-window data means other/null. Codex usageLimitExceeded is sufficient even when rateLimitReachedType is null; absent provider window/reset remain other/null.

Driver identity is `quota:<beeId>:<generation>:<output-journal-line-end-byte-cursor>`, independent of polling batch and replay. Daemon persists one `quota.observed` audit row per identity, payload `{eventId, beeId, generation, quota, turn}` (exported as QuotaObservedEvent from core). The existing audit seq/ts provide ordering/time; audit.tail and watch expose the durable event. Native journal retains raw input. Only the current generation may set/clear flags, invoke policy, or append quota.observed. The generation fence applies to ALL flag evidence, both set and clear, every flag, including sandbox_tmp ownership. It deliberately replaces the removed policy that stale-generation bee-scoped flags still applied. Old-generation raw journal evidence remains intact.

B can consume quota evidence and persist its interruption obligation; C/E must consume typed quota, not the detail string. A adds no recovery coordinator, rotation mechanism, continuation or allocation policy.

## Durable recovery and quiet notice (B)

Core schema v45 adds quota_recoveries. dumpState, mirror snapshot and replayAudit expose quotaRecoveries: QuotaRecoveryRow[]. audit/watch publishes kind quota.recovery, beeId on the audit envelope, payload:

```ts
{
  recovery: QuotaRecoveryRow;
  notice?: {
    kind: 'quota_recovery';
    recoveryId: string;
    state: 'waiting' | 'rotating' | 'resumed' | 'cancelled';
    sourceId: string | null;
    accountLabel: string | null;
    window: 'five_hour' | 'weekly' | 'other';
    retryAt: number | null;
  };
}
```

Recovery is a core audit/snapshot fact, not a native provider transcript event. Replace one quiet notice by recoveryId. accountLabel is the safe selected destination label, persisted on the row for snapshot parity. rotating means selected/rebind in progress, including a durably enqueued continuation awaiting real provider boot evidence. Synthetic readiness permits that one mailbox insert but does not settle interrupted recovery as resumed. resumed means the continuation is accepted and real successor output has been observed; between-turn capacity recovery can settle at readiness without fabricated input. A between-turn recovery has continuationKind none and no fabricated mail. retryAt is epoch milliseconds for next known fleet capacity, set through the coordinator; null means unknown. Never display a provider reset hint as a promise of fleet capacity. Suggested resumed text: Switched to <accountLabel> (previous hit weekly limit). Suggested waiting text: Capacity returns at <retryAt>, or Waiting for account capacity when unknown.

QuotaRecoveryRow is exported from core types.ts. It records id, beeId, sourceGeneration/sourceAccount, eventIds, sourceId (native Claude UUID or quotaSourceId of the exact native line; null for evidence without a transcript source), observationCursor (first quota journal line-end byte cursor, or null), messageIds, progress, interrupted, controlFence, placement {agent,cwd,cellId}, quota, resetHints by window, state, attempt, targetAccount/accountLabel, successorGeneration, claimId/reservationId/commandId, continuationKind, continuationMessageIds, retryAt/reason and createdAt/updatedAt. Correlate observationCursor with the native journal; eventIds carry A's stable observation identities. Id is a stable source-generation/turn key; repeated observations merge without erasing usable resets. No quota observation sets auth_needed.

C seam: listQuotaRecoveries/getQuotaRecovery; waitQuotaRecovery(id,retryAt,reason); claimQuotaRecovery(id,{targetAccount,claimId?,reservationId?}); bindQuotaRecovery(id,commandId); resumeQuotaRecovery(id); cancelQuotaRecovery(id,reason); cancelQuotaRecoveries(beeId,reason). Claim/rebind/bind share the performSwap transaction. QuotaRecovery.reconcile() is the exported daemon hook for boot/tick; it fences placement/control and enqueues exactly once at successor readiness. bee.swapAccount(account:auto) accepts quotaRecoveryId to identify the waiting obligation; ordinary manual swaps cancel it. The coordinator uses existing admission/claim and lease rules. It owns active allocation triggers and wait retry timing. No rotation or turn-end completes an action attempt.

B also threads optional sourceId through FlagEvidenceLike/FlagEvidence and QuotaObservedEvent. It is persisted on the recovery row and its notice for exact projected quota-row anchoring; observationCursor remains available. Later observations do not replace the first anchor.

Active mode initially persists state=waiting, reason=allocation_owner_required, retryAt=null until an owner admission/lease wait receipt arrives. A provider reset alone does not establish that no alternative has capacity. apiaryd's existing nodes/domain.ts and accountAdmission.ts coordinator owns the unsolicited trigger, fresh complete fleet context, owner acquire, target lease readiness, swap, confirm/release and uncertain-outcome handling.

Filter state=waiting; re-read current bee generation/account/control/placement before dispatch. Ignore autoswap_disabled; respect tags/args autoswap=false. Use recovery.sourceGeneration, sourceAccount, placement.agent, beeId and current effective model to construct the EXISTING admission target: {node: executionNodeId, workId: beeId, expectedGeneration: sourceGeneration}. Keep acquire/swap attempt keys stable through uncertain outcomes; a known precommit refusal may release and start a fresh attempt key. Never issue parallel attempts for one recovery. The target checks recovery belongs to this bee, state=waiting, control/placement validity and autoswap; existing claim authority/epoch/expiry/generation/source/model checks remain unchanged. Claim/rebind/bind and claim consumption remain one transaction. B owns exactly-once continuation after successor readiness; no owner send is needed.

To consider the source itself after reset, acquire passes allowSourceAccount:true plus sourceQuotaRecovery:{observedAt:recovery.createdAt,window:recovery.quota?.window ?? 'other',resetsAt:recovery.quota?.resetsAt ?? null}. This does not bypass admission: source requires fresh readable limits fetched strictly after this recovery observation, with the actual exhausted window present and every applicable observed window below completion reserve. ## Proactive admission (E)

QuotaRecoveryRow and quota.recovery notice carry `trigger: 'provider_limit' | 'proactive'`. Provider recovery retains its typed quota. Proactive recovery has `quota: null`, `admission: {fetchedAt: number, maxProjectedPercent: number}`, eventIds/messageIds empty and interrupted=false; it emits no quota.observed event and no continuation mail. Its notice window is other. Existing persisted rows without trigger mean provider_limit.

Before Honeybee-controlled delivery opens a turn, the shared fresh completion projection may prove insufficient headroom using locally known burn as a lower bound. Stale local observations or an unproven boundary trigger no proactive switch. Active mode publishes waiting/allocation_owner_required; only the owner with complete fresh fleet facts may select and reserve. Shadow recovery filters destinations against the same fresh projection, retaining existing readiness, claims and leases. A running turn keeps its completion reserve. Autoswap=false bypasses the proactive gate. Native provider self-wakes outside Honeybee delivery cannot be prevented before provider use; authoritative quota recovery remains the fallback.

B recovery eligibility holds newer mail during rebind, then admits pending continuation IDs before newer mail. Automatic successor boot retries retain the same obligation and continuation IDs under the existing boot budget; manual stop, archive, swap or placement/control changes cancel. Invalid sibling obligations cancel individually. Source-generation observations received during stop/revive still merge quota/reset hints without touching successor flags. Source session identity is projected before quota policy in the same serialized observation transaction.

B continuationHistory records prior {generation,messageIds,kind} when a successor consumed continuation mail but is confirmed stopped without real boot evidence. The same transaction fences that failed delivery and enqueues one conservative continue with new current continuationMessageIds. Reconciliation or daemon replay sees the new pending IDs and cannot duplicate that retry. Original messages are never replayed again after an unknown consumed delivery. This uses the existing finite boot budget and preserves action attempt tokens.
